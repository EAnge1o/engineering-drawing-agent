## 一、一页速览

| 服务 | 在本项目中的作用 | 依赖 | 未配置时的行为 | 代码位置 |
|---|---|---|---|---|
| **MaaS 模型即服务**<br>（多模态） | 位图图纸的尺寸标注理解；模型只出候选值，不参与最终裁决 | 无（标准库 urllib） | 退化为本地 OCR / 人工录入 | `app/llm.py`<br>`app/drawing.py` |
| **OBS 对象存储** | 证据包持久化、对象 key + ETag 写回 manifest、预签名下载 | `esdk-obs-python`<br>或 `boto3` | 证据包仅存本地（仍可用 SHA-256 校验） | `app/obs.py`<br>`app/evidence.py` |
| **FunctionGraph 函数工作流** | 修复闭环/导出等长任务异步化，避免请求阻塞 | 无（标准库 urllib） | 回退到本地线程池执行 | `app/fn.py`<br>`app/jobs.py`<br>`functions/handler.py` |

`GET /api/cloud/status` 可随时查看接入状态（不会泄漏密钥，AK 做掩码）。

## 三、逐服务接入

### 3.1 MaaS 多模态：让位图图纸也能建模

**为什么需要**：`app/drawing.py` 原有的位图路径依赖 `pytesseract` / `tesseract`，
对工程图字体（如 `φ6.5`、`4×φ6.5`）识别率很低；识别失败就只能"人工录入"，
产品退化为"矢量 PDF 专用"。

**做了什么**：

1. `app/llm.py` 新增 `complete_vision()`：把图纸（PDF 自动光栅化）缩放后以
   base64 内联进 OpenAI 兼容的 `image_url` 消息。
2. `app/drawing.py` 新增 `vision_candidates()`：让模型输出**结构化 JSON**
   （L/W/T、孔径、孔心坐标、边距，每项带 confidence）。
3. `infer_blueprint(dd, vision=...)` 融合候选值，并强制：

   ```python
   status = "inferred"     # 模型值绝不冒充 observed
   source = "maas:vision"
   ```

4. 融合后仍走原有链路：`decide_mode(c, p)` → A0/A1/A2 档位 → 确定性内核复核。

**关键设计——模型不参与最终裁决**：

```
多模态模型出候选值 + 自评置信度
        ↓
置信度模型决定自动化档位（A0 全自动 / A1 辅助 / A2 手动）
        ↓
几何内核 + 数值规则做最终判定（模型值可被推翻）
        ↓
低置信进人工确认队列
```

**验证**：

```bash
cd backend
python -m pytest tests/test_cloud_integrations.py -k vision -q
python -c "from app.drawing import parse_drawing; r=parse_drawing('../samples/plate_normal.png'); print(r.notes)"
```

正常应看到 `已启用 MaaS 多模态解析：模型值标记为 inferred，需确定性内核复核`。

**演示要点**：上传一张**位图** PNG（不是 PDF），前端"解析"面板里
`source` 显示为 `maas:vision`、`status` 显示为 `inferred`，即为云服务生效的直接证据。

### 3.2 OBS：证据链从"本地自证"升级为"云端可校验"

**为什么需要**：现有 `manifest.json` 只记录本地 SHA-256。证据留在本机磁盘，
评委无法独立验证，也无法证明"生成后没被改过"。

**做了什么**：

- `app/obs.py`：上传（`putFile` / `putContent`）、预签名 URL、`headBucket` 连通性自检；
  官方 SDK `esdk-obs-python` 优先，缺失时用 `boto3` 走 OBS 的 S3 兼容协议。
- `app/evidence.py`：`build_evidence(..., upload=None)`，自动模式下配置了 OBS 就上传，
  并把 **对象 key + ETag** 回填到 manifest 的每个文件条目，最后上传 manifest 自身作为"根证据"。
- 端点 `POST /api/tasks/{id}/export?upload=true` 会返回产物的预签名下载链接。

**证据包对象结构**：

```
obs://<bucket>/evidence/<task_id>/report.json
obs://<bucket>/evidence/<task_id>/model.step
obs://<bucket>/evidence/<task_id>/model.stl
obs://<bucket>/evidence/<task_id>/manifest.json   ← 根证据，含各文件 key + ETag
```

**验证**：

```powershell
# 连通性自检（会真的发一次网络请求）
Invoke-RestMethod "http://127.0.0.1:8000/api/cloud/status?probe=true" | ConvertTo-Json -Depth 6

# 生成证据包（自动上传）
Invoke-RestMethod -Method Post "http://127.0.0.1:8000/api/tasks/T-001/evidence" | ConvertTo-Json -Depth 6
```

返回的 `manifest.storage` 里应出现 `bucket` / `objects[].key` / `manifest_key` / `manifest_url`。

**演示要点**：把 `manifest_url` 在浏览器里打开 —— 直接看到云端对象，
且 JSON 里的 `etag` 与 OBS 控制台对象详情页一致。配合**桶的版本控制**，
可进一步说"历史版本可追溯，篡改可发现"。

### 3.3 FunctionGraph：长任务异步化

**为什么需要**：`POST /api/tasks/{id}/fix` 是同步的。CadQuery 建模 + STEP/STL 导出
可能耗时数秒到数十秒，前端只能干等，演示时容易"卡住"。

**做了什么**：

- `app/jobs.py`：任务队列（queued → running → done/failed），本地用线程池；
  配置 `FN_ENDPOINT` 后自动把 payload 交给函数工作流。
- `app/fn.py`：HTTP 触发器客户端。
- `functions/handler.py`：函数入口，按 `kind` 分发（目前支持 `fix` 与 `ping`）。

**新端点**：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/tasks/{id}/fix/async` | 立即返回 `job_id`，不阻塞 |
| GET | `/api/jobs` | 最近任务列表 |
| GET | `/api/jobs/{job_id}` | 单任务状态与结果 |

**部署步骤**：

1. 把整个 `backend/` 目录（含 `app/`、`functions/`）打成 zip；
2. FunctionGraph 控制台 → 创建函数 → 运行时 Python 3.10+，入口 `handler.handler`；
3. 超时 ≥ 60s，内存 ≥ 512MB（几何内核建议 1GB）；
4. 添加 **HTTP 触发器**，把 URL 填入 `FN_ENDPOINT`；
5. 验证：`POST /api/tasks/{id}/fix/async` 返回 `"mode": "functiongraph"`。

**注意**：若函数包未包含 CadQuery，`app/cad.py` 会自动退化为确定性几何摘要，
闭环仍然成立（这是本项目"内核可选"设计带来的好处）。

### 3.4 CES 云监控：调用量 / 时延看板

**为什么需要**：Agent 多轮修复的失败原因需要可回溯；评委常问"你怎么观测线上表现"。

**做了什么**：

- `app/metrics.py`：`emit()` / `timing()` / `Timer` 上下文管理器；
  **始终**写本地 JSONL 缓冲（`backend/outputs/metrics_buffer.jsonl`），
  配置 CES 后额外批量上报。
- 已插桩的指标：

| 指标名 | 类型 | 含义 |
|---|---|---|
| `task.created` | Count | 建任务数（维度 source=blueprint/drawing，vision=on/off） |
| `parse.duration` | ms | 解析耗时 |
| `fix.duration` | ms | 修复闭环耗时（维度 mode） |
| `fix.completed` | Count | 完成的修复（维度 state） |
| `issue.detected` | Count | 检出问题数 |
| `fix.rounds` | Count | 消耗的修复轮次 |
| `fix.remaining` | Count | 遗留问题数 |
| `export.duration` | ms | 导出/证据打包耗时 |
| `evidence.generated` | Count | 证据包生成（维度 ok） |
| `job.duration` | ms | 异步任务耗时（维度 kind/status） |

**看板数据（不依赖云环境）**：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/metrics/summary" | ConvertTo-Json -Depth 6
```

返回 `counters` / `latency`（avg/p50/p95/max）/ `errors` / `error_rate`。
**这段输出可以直接截图进 PPT**，即使 CES 还没配好。

**上报 CES**：

```powershell
Invoke-RestMethod -Method Post "http://127.0.0.1:8000/api/metrics/push"
```

成功返回 `{"ok": true, "pushed": N, "namespace": "Sourth/CADAgent"}`。
之后在 CES 控制台 →「自定义监控」→ 命名空间 `Sourth/CADAgent` 下即可配图表与告警。

## 五、费用与额度（比赛期间务必注意）

1. **MaaS** 按 Token 计费，未开通的服务不产生费用。调试期建议用
   `deepseek-v4.1-flash` 这类低价模型，别拿多模态反复刷大图。
2. **OBS** 有免费试用包；注意**流量费**（预签名下载走公网流量）。
   证据包不大（单任务几百 KB），但别把 `outputs/` 整个桶同步上去。
3. **FunctionGraph** 有永久免费额度（约每月 100 万次调用 + 40 万 GB·秒，
   以官网为准），比赛用量远低于额度。
4. **CES** 自定义指标按上报条数计费，`push_ces` 默认只推最近 20 条，够用且省钱。
5. 比赛结束后记得**释放 ECS / 删除 OBS 桶 / 关闭预置服务**，避免试用到期自动扣费。

## 六、答辩话术：必要性论证表

> 评委看的不是"用了几个服务"，而是"为什么非它不可"。

| 服务 | 解决了什么问题 | 如果不用会怎样 |
|---|---|---|
| **MaaS（多模态）** | 位图图纸的尺寸标注无法用规则提取，tesseract 对工程图字体识别率极低 | 位图图纸只能人工逐项录入，产品退化为"矢量 PDF 专用"，丢掉一半目标用户 |
| **OBS** | 证据包需要长期、不可篡改、可被第三方独立校验的存储 | 证据只存在于本地磁盘，任务重跑即覆盖，"可验证"沦为自说自话 |
| **FunctionGraph** | 建模+导出耗时数秒到数十秒，同步请求会阻塞对话 | 需要常驻进程空转等待，且无法按需弹性扩容 |
| **CES** | 多轮修复的失败原因需要回溯定位与量化观测 | 出问题只能靠本地 print，无法回答"线上成功率多少" |

配套的一句话总结：

> **模型负责"看懂图纸"，内核负责"保证正确"，云服务负责"让它可信、可观测、可扩展"。**

## 七、降级行为与测试保障

所有云服务均为**可选依赖**，未配置时：

| 场景 | 行为 |
|---|---|
| 无 `LLM_BASE_URL` | 走纯确定性解析 + 本地 OCR；`vision_candidates()` 直接返回 `None` |
| 无 OBS 凭据 | `put_file()` 等立即返回 `{"ok": false, "error": "OBS 未配置..."}`；证据包仅本地 |
| 无 `FN_ENDPOINT` | `/fix/async` 走本地线程池，`mode` 字段为 `local` |
| 无 CES 凭据/SDK | 仅写本地 JSONL；`/api/metrics/summary` 照常可用 |

回归测试覆盖了全部降级路径：

```bash
cd backend
python -m pytest -q
# 96 passed, 1 skipped
```

其中 `tests/test_cloud_integrations.py` 共 34 项，包含：

- 未配置时各服务快速失败、不抛异常
- 模型输出归一化（非法值/负坐标/`null` 被正确丢弃）
- **端到端**：mock 模型返回 → `parse_drawing` 产出带 `maas:vision` 证据的 Spec
- `use_vision=False` 时确认完全不调用模型（可复现的确定性路径）
- 无轮廓时依靠多模态候选仍可建模；既无轮廓又无候选时仍明确报错
- **多模态熔断**：连续失败 3 次后冷却 60s，避免凭据失效时每次解析都卡到超时
- FunctionGraph handler 契约（含 HTTP 触发器 body 为字符串的形态）
