# 评估指标说明（65 例测试集）

运行：`cd backend && python scripts/evaluate_suite.py` → 输出 `outputs/metrics.json`。

## 1. 测试集构成（65 例，程序化生成）

| 类别 | 数量 | 构造方式 | 期望行为 |
|---|---|---|---|
| 正常图（负样本） | 20 | 板长 110–300，4 孔对称 | 无问题，**不应被修改** |
| 孔位越界 | 15 | 右上孔 x = L−5（与边距 15 冲突） | 检出并修复回 L−15 |
| 边距级联 | 10 | 边距 15 → 5 | 一次改参数触发 4 条孔位约束失败，逐条修复 |
| 间距冲突 | 5 | 把 h3 移到 (20,20)，与 h1 间距 7 < 20 | **拒绝自动修复**（需人工） |
| 边界可修 | 5 | 圆角 10.2 > 上限 10 | 检出并修复到 10.0 |
| 低置信拒绝 | 5 | 缺陷存在但证据置信度 0.40 | **拒绝自动修复**，进入待确认 |
| 边界负样本 | 5 | 圆角恰为 10.0（等于上限） | 通过且不被误修 |

## 2. 指标定义

| 指标 | 定义 | 含义 |
|---|---|---|
| 检出率 | 发现的真问题数 / 真问题总数 | 审查有效性 |
| 自动修复成功率 | 验证通过的修复数 / 修复尝试数 | 修复有效性 |
| 回归错误率 | 回滚（引入回归或未解决）数 / 修复尝试数 | 修复安全性 |
| 预算达标率 | 在预算内结束的任务数 / 总任务数 | 预算可控性 |
| **影响集 recall（覆盖率）** | 实际新增失效约束中被影响图捕获的比例 | **核心：依赖图是否漏掉需回归的约束** |
| 影响集 precision（超集效率） | 预测集中实际失效的比例 | 预测集是否精简（<1 表示保守超集） |
| 冲突仲裁正确率 | 冲突修复后参数落回"多数证据值"的比例 | 修复是否遵循证据裁决 |
| 正确拒绝率 | 应拒绝样本中确实未自动修改的比例 | 不确定性管理是否生效 |
| 误修率 | 负样本中被自动修改的比例 | 是否过度修复 |

## 3. 当前结果（65 例）

```
n_runs                 : 65
detection_rate         : 1.0
repair_success_rate    : 1.0
regression_error_rate  : 0.0
budget_compliance_rate : 1.0
impact_precision       : 0.5286
impact_recall          : 1.0
arbitration_accuracy   : 1.0
refusal_accuracy       : 1.0
misrepair_rate         : 0.0
```

**如何解读**
- **impact_recall = 1.0**：变更后真正会失效的约束**全部**被依赖图纳入回归集 → 不会漏检。
- **impact_precision ≈ 0.53**：影响图给出的是**保守超集**（把"可能受影响"都纳入回归），因此 precision<1 属预期；
  它换来的是回归**不漏项**。若追求精简，可在图上做"约束可达 + 参数实际参与"的二次剪枝。
- **refusal_accuracy = 1.0 / misrepair_rate = 0.0**：对间距冲突与低置信场景正确拒绝，且未误改正确内容。
